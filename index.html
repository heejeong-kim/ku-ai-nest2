1.1 아이디어·시장 구조화

  • 아이디어가 속한 에코푸드 세부시장과 직접·간접 경쟁환경을 함께 조사할 것
  • 분석 결과에서 다음 단계에 검증할 페인포인트와 미충족 니즈 후보를 도출할 것
  • 새로운 아이디어를 다시 만들지 말고 공통과정에서 정리한 아이디어 2~3개를 준비할 것
  • 각 아이디어를 그대로 조사하지 말고 [핵심 고객 → 사용 상황 → 해결하려는 문제 → 제공하려는 해결방법] 순서로 먼저 구조화할 것
    • 핵심 고객: 누가 이 문제를 가장 크게 경험하는지 정의
    • 사용 상황: 고객이 언제, 어떤 상황에서 문제를 경험하는지 정의
    • 해결하려는 문제: 고객이 현재 겪는 불편·비용·시간 손실을 구체적으로 정의
    • 해결방법: 해당 문제를 어떤 서비스 또는 기능으로 해결하려는지 한 문장으로 정리
  • 구조화한 결과를 Claude에 입력한 뒤 각 아이디어가 어떤 에코푸드 세부시장에 속하는지 분류하도록 할 것
  • 하나의 아이디어가 여러 시장에 걸쳐 있는 경우 핵심 고객문제가 실제로 발생하는 시장을 1차 조사시장으로 선정할 것
  • 아직 아이디어가 구체적이지 않은 경우 아래 세부시장 예시를 참고해 가장 가까운 영역을 선택한 뒤 구조화를 진행할 것

가격·지불의사, 실제 이용행동, 기술 구현, 인허가, 원산지·성분·인증 표시 관련 사항 중 사업화 전에 확인할 핵심 과제만 정리하고 확인되지 않은 내용은 [추가 검증 필요]로 표시해줘

사업계획서 작성 시 아래 기준을 반드시 지켜줘
- 시장이 크다는 사실만으로 고객 문제가 검증됐다고 작성하지 말아줘
- 앞 단계에서 확정한 고객·문제·아이템을 임의로 바꾸거나 타겟을 넓히지 말아줘
- 문제보다 기능과 장점을 먼저 설명하거나 기능 개수를 차별성으로 표현하지 말아줘
- 출처 없는 수치나 검증되지 않은 매출·점유율·성장률을 근거처럼 사용하지 말아줘
- 비즈니스모델은 가격만 제시하지 말고 [고객가치 → 지불 이유 → 수익구조]가 연결되도록 작성해줘

각 항목은 메모나 키워드 나열이 아니라 제출 가능한 사업계획서 문장으로 작성해줘

5.1 MVP 범위·유저 플로우·AI 역할 정의

  • 실제 타겟 고객이 핵심 페인포인트를 충분히 크게 경험하고 제안한 해결방식에 반응하는지 확인할 핵심 가설 1개를 정의할 것
  • 가설 검증에 필요한 사용자 행동 1개와 핵심 기능 3개만 선정하고, 최소 1개는 [AI 입력 → AI 처리 → AI 출력]이 명확한 AI 기능으로 설계할 것
  • 사용자 데이터 수집이 필요한 경우에만 Google Sheets를 선택적으로 연동하고, [타겟 고객 여부 / 문제 발생 상황·빈도·강도 / 현재 해결방식 / 핵심 기능 사용행동 / AI 결과 만족도·추가 니즈] 중 가설 검증에 필요한 최소 데이터만 저장할 것
  • 성분 분석·인증 판정·전문가 판단, 대규모 외부 DB 등 핵심 가설 검증에 필요하지 않은 기능은 [후속 개발] 또는 [추가 검증 필요]로 분리할 것
  • 결제 의사를 확인해야 하는 경우에도 실제 PG(결제대행사) 연동 없이 모의(더미) 결제 화면으로만 구현할 것
  • 이름·연락처 등 개인정보를 입력받는 화면에는 수집 목적을 밝히는 동의 문구와 동의 체크박스를 반드시 포함할 것
  • 유저 플로우는 [서비스 진입 → 정보 입력 → AI 포함 핵심 기능 이용 → 결과 확인 → 피드백]을 기준으로 5단계 이내로 정리할 것

- 문제 발생 상황·빈도·강도를 확인하는 데이터

핵심 기능 3개 중 최소 1개는 AI가 실제 고객문제 해결에 기여하는 기능으로 정의해줘
AI를 단순 챗봇이나 장식 기능으로 추가하지 말고 입력된 고객정보를 정리·분류·요약·비교·개인화 안내하는 등 핵심 가치 제공에 직접 사용해줘
AI 적용 기능은 반드시 아래 구조로 정리해줘
- AI 입력: 사용자가 제공하거나 서비스가 AI에 전달하는 정보
- AI 처리: AI가 수행하는 정리·분류·요약·비교·개인화 역할
- AI 출력: 사용자가 실제 화면에서 확인하는 결과
성분 분석·인증 판정·전문가 판단처럼 AI가 대신하면 안 되는 영역은 제외하거나 정보 정리·의사결정 지원 수준으로 제한해줘
- 현재 해결방식을 확인하는 데이터
- 핵심 기능 사용 여부를 확인하는 행동 데이터
- 결과 만족도·추가 니즈를 확인하는 데이터

- 기능 목적

- 화면명
- 화면 목적
- 주요 UI 요소
- 사용자 입력
- 서비스 출력
- 다음 화면으로 이동하는 조건 또는 버튼

아래 조건을 먼저 판단해줘
- 5.1에서 정의한 MVP 검증 가설이 사용자 행동 데이터를 저장하지 않고도(예: 단순 열람·즉시 피드백 UI만으로) 검증 가능하다면 Google Sheets 연동 없이 [연동 불필요] 사유를 1~2문장으로 설명하고 이 섹션을 종료해줘
- 검증 가설 확인을 위해 최소 행동 데이터를 남겨야만 하는 경우에만 아래를 진행해줘

연동이 필요한 경우에도 데이터 항목은 반드시 5~8개 핵심 컬럼으로 제한해줘
화면 단위 상태값(입력완료, 처리중 등 시스템 로그성 데이터)은 저장 대상에서 제외하고, 오직 [핵심 가설 검증에 직접 쓰이는 사용자 응답·행동] 데이터만 선정해줘

각 데이터 항목마다 아래 내용을 작성해줘
- 데이터명
- 수집 시점
- 입력 방식 또는 발생 조건
- 수집 목적
- 검증 가설과의 연결
- 향후 서비스화 활용 가능성

데이터 항목은 아래 목적 중 하나와 반드시 연결해줘
